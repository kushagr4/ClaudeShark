# v0.5.1 cleanup — test hygiene, arena guards, delta-pruning red team

Date: 2026-09-02. Base: `debff85`. **Production search unchanged**, so no new
engine version was created; this is tooling and test work only.

## 1. The clock-99 fixture

Codex was right. `8/8/8/8/8/8/6pk/6K1 b - - 99 80` is invalid — the kings are
adjacent (`OPPOSITE_CHECK`) — **and** it has two non-zeroing king moves
(`h2h3`, `h2g3`), so it never tested the "every move resets the counter"
scenario its name claimed.

Production fifty-move behaviour was not touched. It was independently correct;
only the test was wrong.

Replaced with six named cases, all verified valid, all deriving their expected
result from `board.outcome(claim_draw=True)` rather than from a written-down
rule:

| case | fen | claim? |
|---|---|---|
| A clock 98 | `6k1/8/8/8/8/8/8/R5K1 b - - 98 80` | no |
| B clock 99, non-zeroing exists | `6k1/8/8/8/8/8/8/R5K1 b - - 99 80` | **yes** |
| C clock 99, **all moves zeroing** | `7k/p7/6Q1/8/8/8/8/1K6 b - - 99 80` | **no** |
| D clock 100 | `6k1/8/8/8/8/8/8/R5K1 b - - 100 80` | yes |
| E in check, legal moves | `q5k1/6R1/8/8/8/8/8/6K1 b - - 100 80` | yes |
| F checkmate | `R5k1/5ppp/8/8/8/8/8/6K1 b - - 100 80` | no — mate wins |

Case C is the one that previously did not exist: black has exactly two pawn
moves, both of which reset the counter, so `can_claim_fifty_moves()` is false
and the game continues. A separate test asserts each fixture actually exercises
its own premise, so a future fixture cannot quietly stop testing anything.

## 2. The wider fixture audit

The flagged fixture was not alone. Scanning every hard-coded FEN in `tests/`
and `tools/` found **12 invalid positions**: two deliberate (used to prove
validation rejects them) and **ten genuine defects**.

| file | problem |
|---|---|
| `test_eval.py` ×6 | queens giving check to the side not to move; kings on adjacent squares |
| `test_engine.py` | the same nine-queens position |
| `test_search_correctness.py` | stalemate-parent position with the queen giving check to the wrong king |
| `test_terminal_ordering.py` | the clock-99 fixture |

Every one passed its test, because evaluation and search do not consult
legality — the assertions were true of positions that cannot occur.

All ten replaced with verified-legal equivalents preserving the original intent
(nine queens still overflow the game phase at 36; the promoting-pawns position
still has eight pawns a rank from promotion).

`tests/test_fixture_hygiene.py` now scans every FEN in the suite on each run,
with an explicit allowlist for the deliberately illegal ones, plus a named
adjacent-kings check because that is the failure that keeps recurring.

## 3. Odd game counts

Colour pairing is the basis of every strength claim here, so an odd `--games`
leaves one unpaired game whose colour bias goes straight into the score. The
arena now refuses it:

```
--games must be even for paired arena matches, got 97. Every position is
played once with each colour; an odd count leaves one game unpaired and
biases the score.
```

No unpaired mode was added, because nothing needs one.

## 4. Unknown `CS_*` variables

Three behaviours, now all tested:

* inherited unknown `CS_*` → **stripped** (was already true);
* known, explicitly requested → accepted and recorded;
* **unknown, explicitly requested → refused**, with the recognised list printed.

The motivating case is a typo. `CS_LRM=0` looks like `CS_LMR=0`; accepted, it
would be set and faithfully recorded while changing nothing, producing a match
between two identical engines under the label of an LMR experiment.

## 5. Delta-pruning red team

Delta pruning decides before the capture is pushed, so it cannot know the move
gives check and is not covered by the SEE check exemption. That hole is real in
the code. The question was whether it is reachable.

`tools/delta_redteam.py` compares the shipping engine against one with delta
pruning effectively disabled, then re-runs only the divergent positions deeper.
The position set deliberately goes beyond the benchmark corpus, which was never
selected for this motif:

```
positions: 42 corpus + 16 tactics + 80 generated = 138
  containing a negative-SEE checking capture: 88
divergent positions at depth 6: 2/138
```

| fen | depth 6 | depth 7 | depth 8 | verdict |
|---|---|---|---|---|
| `rq2R2r/1p4kp/3p4/p1Np4/P1nb1pb1/B7/n3PP2/4KBN1 b - - 1 35` | ON `b8e8` 2564, OFF `d4c3` 2584 | both `b8e8`, 2605 | both `b8e8`, 2605 | **A converges** |
| `rnbq1br1/p4k1p/1pp1pnp1/Q2p1p2/8/1PPP3N/P1N1PPPP/R1B1KB1R w KQ - 0 12` | ON `a5a4` −46, OFF `h3g5` −39 | `a5a4` vs `h3g5`, both −50 | both −48 | **B equivalent** |

**C failures: 0.** One divergence is a depth-6 artefact that disappears; the
other persists but with *identical scores at both deeper depths*, meaning the
search genuinely cannot separate the two moves.

**Decision: delta pruning unchanged.** No fix was implemented, because the brief
was explicit that a change needs a concrete reproduced defect and none exists.
The theoretical hole is documented and `tools/delta_redteam.py` is committed so
the experiment can be repeated cheaply.

(Codex saw 4 divergences over 162 positions before it stopped; this run saw 2
over 138. Different position sets, same shape of answer: converge or
equivalent.)

## 6. Repetition

Unchanged, per the brief. Codex's interrupted verification found one move
difference over 161 positions with both lines around +6 pawns, and zero
differences over 120 generated histories. Combined with this project's own
tests, the second-occurrence heuristic remains a **documented deviation from
FIDE with no demonstrated cost**.

## 7. Corpus calibration — a real gap

The 42 positions are proven legal, unique and non-terminal. They are **not**
proven near-level, and the name `BALANCED_OPENINGS` is aspirational.

**There are no reference evaluations in this repository.** No position carries a
label from any external engine, and none has ever been calibrated. The name has
been carrying an assurance nothing supports.

Our own engine at fixed depth 6 — self-referential, and *not* a calibration —
scores the 24 arena positions from −0.65 to **+6.03**:

| index | score | note |
|---|---|---|
| 14 | **+6.03** | `8/5pk1/6p1/8/8/1R6/5PPP/6K1` — white is a whole rook up |
| 22 | +3.84 | |
| 18 | +3.78 | |
| 12 | +3.39 | |
| 8 | +1.68 | |
| the other 19 | −0.65 to +1.08 | plausibly near-level |

Colour pairing means a lopsided position does not bias the *result* — both
engines play both sides — but it does waste games: two competent engines both
convert a winning position, the pair draws out, and the game carries almost no
information about which is stronger. Five of 24 positions are in that category
and one is decisively won.

**No threshold is proposed and no corpus change was made**, because setting a
balance criterion without an oracle would be inventing the calibration this
section exists to report as missing. Recorded as a task for the corpus-calibration session.
