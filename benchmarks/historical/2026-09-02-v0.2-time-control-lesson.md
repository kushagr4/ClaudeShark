# Historical: the v0.1 → v0.2 results, and the time-control lesson

**These are transcribed console results. No log files were kept at the time.**
They are recorded here for continuity, not as reproducible artefacts. The
commands are the ones that were run; re-running them will produce similar but
not identical numbers, because arena games are wall-clock limited and the
minimax baseline chooses randomly among equal-scoring moves.

## Baselines (v0.1, 24 games each, 10 s + 0.1 s)

```
uv run python -m tools.arena --agent champions/v0_1 --opponent baselines/minimax --games 24 --base-ms 10000 --increment-ms 100 --workers 5
uv run python -m tools.arena --agent champions/v0_1 --opponent baselines/numba   --games 24 --base-ms 10000 --increment-ms 100 --workers 5
```

| opponent | result | score |
|---|---|---|
| `baselines/minimax` | +24 =0 -0 | 100% |
| `baselines/numba` | +24 =0 -0 | 100% |

Both provided baselines are saturated. They remain useful only as smoke tests.

## The mismeasured A/B (200 games, 5 s + 0.05 s ≈ 180 ms per move)

```
uv run python -m tools.arena --agent champions/v0_2 --opponent champions/v0_1 --games 200 --base-ms 5000 --increment-ms 50 --workers 5
```

```
+56 =73 -71, score 46.2%
elo -26  (95% CI -65 .. +12)
```

## The corrected A/B (120 games, 20 s + 0.2 s ≈ 900 ms per move)

```
uv run python -m tools.arena --agent champions/v0_2 --opponent champions/v0_1 --games 120 --base-ms 20000 --increment-ms 200 --ply-cap 200 --workers 5
```

```
+44 =41 -35, score 53.8%
elo +26  (95% CI -24 .. +78)
```

## Why the sign flipped

The same two engines, measured at two per-move budgets:

| budget/move | v0.1 depth | v0.2 depth | gain |
|---|---|---|---|
| 200 ms | 4.54 | 4.71 | +0.17 ply |
| 2000 ms | 6.17 | 7.38 | +1.21 ply |
| 4500 ms | 7.04 | 8.33 | +1.29 ply |

Reductions and null-move pruning need depth before they pay. At 180 ms per move
the candidate gains almost nothing while carrying the full tactical risk of
reducing moves, and its nodes-per-second is *lower* because of the re-searches.

**The lesson: an A/B time control must produce a per-move budget in the same
range as the competition's, or the result does not transfer.** The cheap way to
sanity-check a change before committing an arena to hours of games is
`tools/bench.py --depth N`, which is deterministic and takes minutes.

## Caveat on the "4.5 seconds per move" framing

Earlier notes described the competition as having a fixed ~4.5 s per move. That
is wrong and has been corrected throughout. The competition uses a chess clock
of 120 s + 0.5 s; 4.5 s is merely what the current allocator happens to spend on
an opening move with a full clock, and it falls as the game goes on. 4.5 s
survives only as a *fixed-budget benchmark point*, not as a description of the
time control.
